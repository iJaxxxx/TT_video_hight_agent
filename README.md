# TT_video_hight_agent

两个乒乓球视频小工具，都不需要训练模型：

| 脚本 | 做什么 | 怎么做 |
|---|---|---|
| `highlight.py` | 自动截取最精彩的连续 N 秒（默认 60 秒） | 听：从声音里找击球 → 串成回合 → 滑动窗口打分 |
| `ball_track.py` | 识别球的飞行轨迹并叠加到视频上 | 看：三帧差分 → 过滤掉人 → 匀速模型跟踪 |

## 环境

- Python 3.9+
- 命令行里能用 ffmpeg / ffprobe（macOS：`brew install ffmpeg`）
- `pip install -r requirements.txt`（numpy、opencv-python）

请在本目录下运行，两个脚本都依赖 `common.py`。

## highlight.py：截取高光

```bash
python3 highlight.py ~/Downloads/IMG_6921.mov                # 剪出 60 秒，存在原视频旁边
python3 highlight.py ~/Downloads/IMG_6921.mov --dry-run      # 只打印候选时间段，不导出
python3 highlight.py ~/Downloads/IMG_6921.mov -d 30 -o best30.mp4
python3 highlight.py ~/Downloads/IMG_6921.mov --start 484    # 不自动选，直接从第 484 秒开始导出
```

步骤：
1. **检测击球**：音频转成 16kHz 单声道，每 5 毫秒计算一次 1.5–7kHz 频段能量的突增量（spectral flux）。一个时刻要明显高于附近 2 秒的中位数才算击球，两次击球之间至少间隔 0.18 秒。
2. **串成回合**：相邻击球间隔小于 1.5 秒，算同一个回合。
3. **窗口打分**：60 秒的窗口每次挪 0.5 秒，窗口里每个回合得 `拍数^1.5` 分；窗口边界如果切到某个回合中间就扣分，所以起止点会自然落在两分之间的空档。
4. **导出**：ffmpeg 重新编码，做到精确剪切（H.264 CRF 18，保留原分辨率和帧率）。

常用参数：`--exponent`（越大越偏爱长回合）、`--rally-gap`、`--cut-penalty`、`--crf`、`--preset`。

局限：它衡量的只是"打得密、回合长"，不懂"打得好"。一板制胜的扣杀只算一个短回合，容易被漏掉。

## ball_track.py：球轨迹识别

```bash
# 处理原视频第 484 秒起的 60 秒，叠加击球时刻并统计覆盖率
python3 ball_track.py ~/Downloads/IMG_6921.mov --start 484 --duration 60 --hits \
    --exclude 1050,800,1920,1080 --exclude 0,950,1920,1080
```

输出：
- `<原名>_ball_track.mp4`：红圈是当前球的位置，黄线是最近约 0.25 秒的轨迹，左下角的 `HIT` 是声音检测到的击球
- `<原名>_ball_track.json`：逐帧的球坐标，格式为 `帧号 -> [x, y, 该帧在原视频中的时间(秒)]`，另有 `hit_times`（击球时刻）。以后训练模型时可以当作预标注

步骤：
1. **三帧差分**：只保留在连续三帧里都在变化的像素。地上静止的散球、球台等会自动被去掉。
2. **过滤掉人**：把运动像素膨胀、合并成团，运动量大的整团视为球员，直接丢弃。剩下的点还要满足小、亮、饱和度低（白球）这几个条件。
3. **跟踪**：用匀速预测加就近匹配，把点连成轨迹。太短、太慢、太小的轨迹丢弃；每一帧取得分最高的那条轨迹；不超过 6 帧的空缺用线性插值补上。
4. **`--exclude` 排除区域**：把地上散球滚动的区域排除掉，免得追踪认错球。这组坐标是按这个机位手调的，换了机位要重新量。真正的产品应该通过球台标定自动算出来。

**时间对齐**：手机拍的视频通常是可变帧率（VFR）。IMG_6921 标称 59.94fps，实际约 60fps，帧间隔在 15–18ms 之间浮动。如果按"帧号 ÷ fps"换算时间，第 484 秒处会偏 13 帧，HIT 标记就和画面对不上。所以脚本先用 ffprobe 读出每一帧的真实时间戳，帧号和时间一律查表；解码统一走 ffmpeg 的时间戳 seek，不用 OpenCV 的按帧号 seek。已验证分块读取与连续读取逐帧一致，叠加视频与原视频同一时刻的帧偏移为 0。

在 IMG_6921（8:04–9:04，1080p60）上的实测结果：回合进行中约 42% 的帧定位到了球。在 4 核机器上处理 60 秒大约需要 1.5 分钟。主要漏检有两种情况：
- 球靠近正在挥拍的球员时，被当成人体运动一起过滤掉了
- 球被网带挡住时

阈值（`--diff --min-v --max-s --min-area` 等）是针对固定机位、白球、室内灯光调的，换场景可能需要重新调参。

## App（React Native / Expo）+ 服务端

手机 App 负责选视频、确认得分球、编辑集锦、标定球台和导出成片。界面按 Figma 设计稿实现：首页 / 项目 / 我的 三个 Tab，导入流程为 选视频 → 选自己在远端还是近端 → AI 分析 → 勾选回合 → 编辑集锦（排序、删减、微调起止）→ 导出（9:16 / 16:9 / 1:1，720p / 1080p / 原画）。视频处理都在电脑上的服务端里跑，复用上面的 `common.py`。

```
app/      Expo SDK 58，iOS / Android 共用一套代码
server/   FastAPI：上传 → 击球检测 → 候选分 → （大模型复核）→ 人工确认 → 导出
```

**启动服务端**（需要 ffmpeg；Python 依赖装在 `server/.venv`）：

```bash
cd server && uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python -r requirements.txt
cp .env.example .env        # 大模型 Key 写在这里，留空则全部人工确认
.venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000
```

**启动 App**（需要 Node 22+），手机装 Expo Go 扫码。手机和电脑要在同一个 Wi-Fi 下：

```bash
cd app && npm install && npx expo start
```

App 默认连接「运行 Expo 的那台电脑的局域网 IP:8000」，可以在 App「我的 → 服务器地址」里改。

**球台标定**：在结果页右上角「···」→「球台标定」，按 近端左 → 近端右 → 远端右 → 远端左 点球台四个角。四个角都点好后，先选中一个角，再在画面上点或拖来微调。提交后会显示一张检查图，白框贴住真实球台才算标准。机位不变时，新视频可以「沿用上次的标定」。标定结果（单应性矩阵，像素 ↔ 台面米）存在任务的 `calibration` 字段里，后面估算球速、按落点剔除死球都会用到。

**注意**：新款 iPhone 视频的第一条音轨是空间音频（APAC），ffmpeg 解不了。`common.audio_stream()` 会自动跳过它，改用 AAC 音轨。

**球速估算**（`server/speed.py`，球台标定后在后台自动计算）：对每个分的决胜一板估算出手速度（km/h，和 WTT 转播一样，指球刚离开球拍时的速度）。「最快一板」只在标为「我赢」的分里选。

做法：
- 用标定的四个角和手机镜头先验（f ≈ 0.74 × 画面宽）反推相机位置。
- 找击球声之后朝对方半台飞的那段球轨迹，在画面上找到落台拐点，用台面几何算出落台点。
- 固定落台点，用「重力 + 空气阻力」的飞行模型往回积分，拟合落台前的轨迹，得到击球时刻的速度。
- 焦距在 ±15%、落台点在 ±5cm 范围内各试一遍，得出可能范围和可信度。

没看到落台、决胜一板没追踪到、轨迹和模型对不上时，不给数，并写明原因。旋转（马格努斯力）没有建模，上旋球会偏低。

精度主要受机位影响。现在这种机位低、架在教练身后，球迎着镜头飞，落台常被教练挡住，误差大约 ±20–40%。建议改成侧面机位：在网的延长线上、离球台 2–3 米、比台面高约 0.5 米，并用 120/240fps 录像。
